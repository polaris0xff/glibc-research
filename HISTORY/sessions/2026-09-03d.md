## 1. N0 — the cold column was measuring a warm start

`docs/history/corrections.md` C23 had recorded that four runs of the kdenlive
comparison gave cold-start ratios of 2.52×, 3.48×, 4.92× and 5.02×, with warm
**above** cold in two of them, and named the cause as *"the instrument's
cold/warm distinction collapsing on this subject"*. It did not say why.

⭐ **`experiments/99-` found the mechanism, and it is a five-second timer.**

uruntime keys its mountpoint on the artefact's **content**, not its path, and
leaves the mount alive for a few seconds after the process exits. So:

| gap since the last run | 0 s | 2 s | 4 s | 6 s | 10 s |
|---|---|---|---|---|---|
| cold start, same file, same command | 13.2 ms | 14.3 | 13.5 | **82.2** | 89.0 |

**6.24×, decided by nothing but elapsed time.** And `90-`'s `cold_of()`
obtained "cold" by running a byte-identical **copy**, on the written reasoning
that *"uruntime keys its mount on the image, so a file nothing has run before
is cold by construction"* — so the copy reused the live mount:

| protocol | median | ratio to warm | resolves |
|---|---|---|---|
| `90-`'s fresh copy | 12.7 ms | **1.02×** | ⛔ no |
| the mount reaped first | 85.0 ms | 6.80× | ✅ yes |
| warm | 12.5 ms | — | — |

Two measurements of the same state differ only by noise, and noise has a sign.
That is C23's whole spread. It became `corrections.md` C24.

### The replacement instrument

`experiments/clock.sh`, a second library beside `lib.sh`:

- **median of N**, not one sample; not a mean (one 10× outlier moves a mean of
  five by 2× and a median not at all); not best-of, which reports a floor and
  hides the spread;
- **interleaved arms with a rotating start**, so drift lands on every arm
  rather than on whichever was measured last;
- ⭐ **an A/A control** — one artefact under two names through the identical
  protocol, whose true ratio is 1.00, so what the instrument reports for it
  **is** its resolution floor. `99-` asserts that the A/A pair does **not**
  resolve; if it ever does, every other number in the file is unreadable.

⚠ **The decision rule needed a second component.** The first version used the
A/A ratio alone, and a smoke test caught it calling a 1.07 difference real
while each arm's own MAD was 4–7% of its median. `clk_floor` is now the larger
of the A/A ratio and the two arms' combined MAD — an accidentally tight A/A
pair cannot license a difference the spread cannot support.

⚠ **And the first version of `99-` ran its A/A block in a second `clk_init`**,
which discarded the protocol block's samples, so two assertions came back
`unknown`. Both blocks are one interleave now, which is also better science: a
control measured in a separate pass saw a different few seconds of the machine
and licenses nothing.

## 2. N2 — the size column is not the time column

`PROGRESS.md` called this *"the hypothesis to test first, because it is the one
that makes the struck size work still count"*: on kdenlive, *"start and render
are dominated by mounting a 398 MB dwarfs image against a 192 MB one"*.

⛔ **Asked within one subject**, because kdenlive against the competitor
differs in bytes AND files AND program AND distribution and can attribute
nothing. `experiments/84-` takes one AppDir and changes one axis at a time:

| arm | bytes | files | cold median | ratio |
|---|---|---|---|---|
| base | 7,331,882 | 292 | 81.4 ms | 1.00× |
| bytes — one incompressible blob | 217,051,660 | 293 | 86.3 ms | 1.06× |
| inodes — 40,000 tiny files | 10,447,143 | 40,292 | 83.1 ms | 1.02× |
| twin — the A/A control | 7,331,882 | 292 | 81.2 ms | 1.01× |

⭐ **The answer is arithmetic, not a boolean.** Image size costs 0.024–0.031 ms
per MiB. Carried across the 196 MiB separating the two kdenlive bundles that is
**about 5 ms of a gap never observed below 129 ms** — under 4%.

⚠ **The first version asserted the boolean "the byte axis does not resolve" and
two consecutive runs disagreed**: 1.04× against a 1.06 floor, then 1.05× against
a 1.03 floor, with the A/A control holding at 1.01–1.02 in both. That is not an
instrument failure — it is a real effect sitting within a factor of two of the
floor, and a boolean about a knife edge is the wrong thing to hang a project's
direction on. The assertion is the magnitude now.

⛔ **Consequence:** N1 (*re-measure the levers on the clock*) lost its premise.
It existed because the byte levers might score under the new bar; they cannot.

## 3. N6 — the lever was the runtime, and we were not running the field's

If the cost is fixed per artefact, the runtime is the subject. And
`internal/bundle/appimage.go` pinned **uruntime v0.5.6, the full build**, while
`experiments/86-` — which stages the competitor's own toolchain out of
`references/pkgforge-dev__Anylinux-AppImages` — stages **v0.5.9 lite**, half
the size.

⛔ **The bundler was being compared against a runtime it did not ship, and
nothing in the record had noticed.**

`experiments/77-`, one AppDir packed five ways, one component changed at a time:

| arm | bytes | cold median | vs ours | resolves |
|---|---|---|---|---|
| ours — v0.5.6 full + dwarfs 0.14.1 | 7,331,916 | 84.6 ms | 1.00× | (reference) |
| v0.5.9 **full** + 0.14.1 | 7,360,554 | 85.3 ms | 1.01× | ⛔ **no** |
| v0.5.9 **lite** + 0.14.1 | 5,779,498 | 64.4 ms | **0.76×** | ✅ yes |
| v0.5.9 lite + dwarfs 0.15.6 | 5,779,502 | 65.0 ms | 0.77× | ✅ yes |

⭐ **It is `lite` and only `lite`.** The version bump buys nothing; the dwarfs
upgrade buys nothing; the whole 1,552,384 B the artefact loses is exactly the
difference between the two headers.

### And the pin was decorative

Moving the constants changed nothing, because `download` returned early
whenever the destination existed and was executable — **whatever URL was asked
for**. Every machine that had ever built a bundle kept packing the old runtime
while the source said otherwise. Found because the artefact did not change
size. The cache is keyed on the URL now, via a sidecar written *after* the
rename.

## 4. The second lever, in the packer

`-S26` is a **64 MiB dwarfs block**, and dwarfs decompresses a whole block to
serve any byte in it, so a cold first read pays for one block whatever it asked
for. Nothing in the record said where `-S26` came from.

⛔ **`experiments/81-` had to run three times to be able to answer.** The first
stopped at 1 MiB and the second at 256 KiB, and both were monotonic to their
own floor — *a sweep that has not found its minimum has measured its range, not
its knob*. The third went to 16 KiB and the curve turned:

| block | small subject | large subject | size on a real payload |
|---|---|---|---|
| 64 MiB | 1.00× | 1.00× | — |
| 16 MiB | 1.01× | 1.00× | −0.0% |
| 4 MiB | 0.97× | 0.79× | +6.9% |
| 1 MiB | 0.88× | 0.77× | +11.0% |
| ⭐ **256 KiB** | **0.76×** | **0.66×** | **+17.8%** ← shipped |
| 64 KiB | 0.73× | 0.64× | +36.9% ← the minimum, not taken |
| 16 KiB | 0.84× | 0.75× | +54.6% ← the turn |

⛔ **64 KiB is the minimum and is not shipped**: it buys 0.02× more and costs
another 19% of the artefact. The ruling makes size *acceptable*, not free, and
goal 3 still names *smaller* for kdenlive.

## The reviews, and what they found in this session's own work

⭐ **Every one found a defect in work done the same day.**

**Is the code right.** `experiments/90-` carried `clk_run_twin`, dead code that
was also wrong — it quoted `"$(sel_of "$TWIN")"`, passing an *empty argument*
where the live path leaves it unquoted so word splitting drops it.

**What did the change stop measuring.** Moving the two pins silently
invalidated the committed evidence of every bundle experiment — 78-, 85-, 86-,
89-, 90- — and **no gate can see it**: `check-docs.sh` compares an experiment's
script against its evidence, and none of those scripts changed. It is C5's
shape reached through the Go source instead of through the build environment.
`pgb bundle appimage` now prints the two runtime filenames, so a run.log says
which runtime it describes.

**Do the instruments still measure what their comments say.** `86-`'s **warm**
column computes `(six invocations − cold) / 5`, which assumes the cold run is
the first of the same series. It is not: the cold sample is one chroot enter
and the six-invocation total is a *second* enter begun inside the 4–6 s reuse
window, so the formula subtracts a cold run that is not in the series it
divides. Its **cold** column is sound — a whole-rootfs reap really does kill
the mount — so the parity headline stands and the warm figure was demoted to
*no difference measurable* on four pages.

**The claims nobody has attacked.** `77-` borrowed `$CACHE/tools/mkdwarfs` for
its three "0.14.1" arms on the reasoning that it was what `pgb` shipped. The
moment the pin moved, that path became 0.15.6 — three arms silently changed
meaning and `field` stopped differing from `v059lite` by anything at all. They
came back 63.2 and 63.6 ms, which reads as a measurement and was an identity.
`lib.sh` gained `exp_pack_blocksize`, which reads the block size out of the Go
source rather than copying it, for the same reason `exp_cfg_const` exists.

**A claim in a code comment, unmeasured.** *"What `lite` drops is compression
backends"* was a guess. Measured: the same AppDir at `zstd:level=19`,
`lzma:level=6` and `null` runs under **both** headers, six for six. What lite
drops is not established; the guard that holds is `77-`'s eleven-environment
arm.

**A number taken by an artefact nobody could tell was broken.** `90-`'s cache
stamped on `[ -s "$OURS" ]` — *exists and is not empty*, which is not *is
complete*. An interrupted `mkdwarfs` leaves a truncated AppImage and a stamp
claiming those options were measured. One was produced at 99,571,958 bytes
where a whole one is about 400 MB. It now stamps only after the artefact
**runs**.

## ⭐ The reference sweep, and the five things it corrected

⛔ **The operator asked for every named reference mined, three passes each, and
the passes paid.** `docs/research/nix-bundle-patching.md` and
`bundle-capabilities.md` carry the findings; these are the corrections to work
this session had already published.

| corrected | was | is |
|---|---|---|
| the mount/extract selector | "an environment variable read at run time, so not shippable" | a **compile-time constant laid out as patchable ASCII**, present in the artefact `pgb` ships. A one-byte overwrite |
| what `lite` drops | guessed "compression backends", withdrawn as unmeasurable | **`dwarfsck` and `mkdwarfs`** — the fork's own build task list, and the `#[cfg]` gates |
| the icon rule | "the smallest `.png`/`.svg`" | ⛔ inverted. The sort is on **path length**, and the intent is **at least 128×128** — the exclusion of `16x16`…`96x96` is the load-bearing part |
| the desktop rule | "the smallest `*.desktop`" | `-quit` ends the search at the **first** match, so the sort receives one line. Three selection rules across two repositories, none of them what the code appears to state |
| gearlever's gate | "requires the type-2 magic (`get_appimage_type`)" | that function is **never called**. The gate is GIO's content type — and `file --mime-type` would have said we fail, while `gio info` returns `application/vnd.appimage` for ours and the competitor's alike |

⭐ **And one measurement landed on a constant it had never seen**:
`experiments/99-` bisected uruntime's mount teardown to "between 4 s and 6 s";
`main.rs:32` says `REUSE_CHECK_DELAY = "5s"`.

⚠ **A caution the operator supplied and the record now carries**: the
`HALL-OF-FAME.md` verdicts were earned deploying **Arch packages** through
`quick-sharun`, not nix closures — *"in nixappimage python is easy and works"*
against a **"Utter garbage"** grade. They are hypotheses to re-derive, and
G2.1's goal is to move the bottom rows up.
