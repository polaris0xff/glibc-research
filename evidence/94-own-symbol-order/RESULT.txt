THE QUESTION: el_own_syms[] was ONE table checked first and
unconditionally inside el_provider(). Its two entries have opposite
requirements and nothing distinguished them or asserted the ordering
that made one of them safe.

arm                                   fixed loader              reversal (pre-T-073)
A yield  a loaded object defines it    provider_calls=1          provider_calls=1
B standin nothing else defines it      standin_fire=1            standin_fire=1
C win    a loaded object defines it    decoy_calls=0 tls=0x5eeded decoy_calls=2 tls=0x5eeded
D own    nothing else defines it       tls=0x5eeded              tls=0x5eeded

C IS THE DEFECT, and the value column is why it was never noticed:
tls=0x5eeded is correct in BOTH. The decoy returns its own slab to
every caller, so a round trip through it is self-consistent. Only
decoy_calls -- 0 fixed, 2 reversed -- says which loader answered.

the eleven: rows=11 yield-ok=11 win-ok=11
